# eCODEsystem extraction — preserve the transformation

Status: **[DESIGN] architectural extraction; not adopted cross-project law**

## Central result

The palimpsest case pressures one architectural statement harder than any specific occult or historical connection:

> **A system that wishes to preserve continuity should not attempt to prove sameness where the evidence only gives transformation. It should preserve the transformation.**

This fits the eCODEsystem more deeply than a conventional ontology-first model.

The system increasingly looks like a **lawful transformation engine whose ontologies are temporary projections over witnessed continuity**.

## Why

History repeatedly gives us objects like this:

```text
specimen A
  -> altered carrier
  -> renamed representation
  -> changed interpretation
  -> partial inheritance
  -> later reconstruction
```

The error is to flatten that sequence into:

```text
A == final thing
```

The eCODEsystem already has better machinery available:

```text
SUBJECT
REPRESENTATION
ANCESTRY
TRANSFORMATION
ENVIRONMENT
INVARIANTS
LOSSES
WITNESS
CAPABILITY
SUCCESSION
```

The palimpsest case adds pressure to keep those fields separate.

## New hard invariants

### 1. Naming does not establish identity

A later label applied to an older shape does not make the old specimen evidence for the later doctrine.

Software analogue:

> Renaming a projection does not reconstitute its subject.

### 2. Resemblance does not establish ancestry

A visual, semantic, or architectural similarity can be real and useful while the genealogy is false or unknown.

Software analogue:

> `FORMAL_RESEMBLANCE` and `STRUCTURAL_ISOMORPHISM` must not silently become `DEMONSTRATED_ANCESTRY`.

### 3. Projection does not become substrate because it is compelling

A graph, symbol, dashboard, GitBook page, render, or AI summary can be an excellent projection without becoming the authority-bearing object.

This directly supports the existing carrier/meaning and projection/authority boundaries.

### 4. Preserve the specimen before interpreting the specimen

Raw source object first; interpretation second.

This aligns with:

```text
foreign sense -> testimony -> native reflex -> constituted authority
```

and:

```text
INGEST -> DIGEST -> GROW -> COMPOST
```

The new contribution is that **reinterpretation itself should be a first-class witnessed transformation**.

### 5. Failed ancestry is useful state

A disproven or unsupported connection should not vanish from the graph.

It should survive as a durable refused edge with its reason and evidence.

That is a research form of Residual / Refusal Topology:

> the shape of what could not lawfully cross from resemblance into ancestry.

## Practical architecture

### A. Add typed relation semantics where cross-project graphs currently flatten edges

Candidate shared vocabulary:

```text
DEMONSTRATED_ANCESTRY
CLAIMED_ANCESTRY
SHARED_PRECURSOR
DOCUMENTED_INFLUENCE
TRANSLATION
TRANSLITERATION
REENCODING
REINTERPRETATION
FORMAL_RESEMBLANCE
STRUCTURAL_ISOMORPHISM
CONTEXTUAL_ASSOCIATION
RETROSPECTIVE_NAMING
CONTRADICTION
REFUSED_ANCESTRY
UNKNOWN
```

Do not universalize this prematurely. National Treasure is the incubator; a second materially different specimen should earn extraction into shared law.

### B. Make transformations addressable objects

A future neutral record can preserve:

```yaml
transformation_id: "..."
from_ref: "..."
to_ref: "..."
operation: "..."
invariants_preserved:
  - "..."
properties_acquired:
  - "..."
losses:
  - "..."
environment_ref: "..."
witness_refs:
  - "..."
authority_ref: null
```

Important: a historical or analytical transformation may have witnesses without having execution authority. `authority_ref` is not mandatory for descriptive history.

### C. Separate object identity from representation identity

A useful future distinction:

```text
subject_id
representation_id
representation_type
carrier
validity_scope
lineage
```

This supports project migration, format changes, GitHub succession, artifact transcodes, score/audio relationships, and research source preservation.

### D. Give National Treasure a permanent job: pareidolia test bench

National Treasure can test new epistemic relation primitives under adversarially attractive material.

If a relation model survives sacred geometry, ciphers, occult language claims, lost-lineage stories, historical coincidence, and visually seductive alignments without collapsing into either credulity or sterile dismissal, it is probably useful elsewhere.

That makes National Treasure more than a research notebook.

It becomes an **epistemic fuzz tester** for the eCODEsystem.

### E. Shape feature extraction as a non-semantic sense organ

A future local tool may decompose glyphs, diagrams, frames, motifs, or topology into formal features and propose relations.

But the authority boundary should be:

```text
shape detector proposes FORMAL_RESEMBLANCE
human / source-backed process may establish ancestry
no detector may manufacture historical transmission
```

This is the same architecture as the broader eCODE principle:

> models propose; bounded systems admit; witnesses preserve.

### F. Witness Sigils as human-readable projections

A deterministic geometric projection of an existing canonical digest is low-risk enough to prototype because it creates no new authority.

Potential owners:

- Project0: canonical meaning and version semantics if the projection ever becomes shared law;
- TranchNode: persistence/indexing of sigil metadata and source digest;
- application repos: rendering only;
- GitBook: explanation/projection only.

Rule:

> **The digest can exist without the sigil. The sigil must never exist authoritatively without the digest it projects.**

### G. Escher's usable lesson: local adjacency can generate global form

No occult ancestry is required.

For Toaster candidate ecology and other generative systems:

```text
local rule
+ bounded neighborhood
+ repeat / mutate / reflect
+ continuity constraints
= emergent global topology
```

This suggests candidate-family mutation can use lawful local neighborhoods rather than one monolithic global aesthetic score.

### H. Bacon's usable lesson: real encoding does not prove alleged message

This is an anti-overfit pattern for AI/research systems.

A decoder must separate:

```text
method exists
method can encode
method can decode this specimen reproducibly
historical actor actually used method here
decoded semantics are independently supported
```

Each is a different claim.

That structure should be reusable anywhere models search corpora for hidden patterns.

## Proposed continuity chain

The existing continuity stack:

```text
Information -> Computation -> Code -> Execution -> AI -> Entrustment
```

can gain a lower-level representation spine:

```text
PARTICULARITY
  -> FORM
  -> RELATION
  -> REPRESENTATION
  -> TRANSFORMATION
  -> WITNESS
  -> CONTINUITY
  -> AUTHORITY (only where constituted)
```

Not every continuity object reaches authority.
Research specimens often stop at witness.
Visual projections often stop at representation.
AI proposals stop before admission.

That is a feature.

## Graduation gates

Do not move this vocabulary into Project0/shared law until at least two materially different domains demonstrate need.

Strong candidates for the second specimen:

1. artifact format migration / transcode continuity;
2. Toaster candidate-family mutation lineage;
3. repository/project succession;
4. source-to-native research compost;
5. score-to-performance-to-audio representation lineage.

A shared primitive graduates only when the common invariant is clearer than the local metaphors.

## Architectural verdict

The weird research does not tell us that all symbols secretly say the same thing.

It tells us almost the opposite:

> **Forms can survive while meanings change; meanings can survive while forms change; names can move independently of both. Continuity lives in the witnessed transformations between them.**

That is immediately useful eCODEsystem architecture.
