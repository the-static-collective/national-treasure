# 0. WHY THIS SLICE EXISTS

REALITY.2 and postEmahh'n converged without becoming the same system.

The useful shape is not:

```text
REALITY.2
  ->
postEmahh'n
  ->
one mandatory progression
```

It is:

```text
REALITY.2          postEmahh'n
    \                /
     \              /
      \            /
       CONVERGENCE
```

Both remain valid starting points.

REALITY.2 teaches composition from particulars:

```text
PARTICULAR
  -> LITTLE YES
  -> RELATION
  -> COMPRESSION
  -> NEW CHARACTER
  -> WORLD
```

postEmahh'n teaches lawful crossing:

```text
PARTICULAR
  -> ADDRESS
  -> RECEIVE
  -> HOLD
  -> POUR
  -> DESCENDANT
  -> LINEAGE
```

The crossing found here is:

> **COMPOSITION CAN TRAVEL.**

and:

> **TRAVEL CAN GENERATE NEW COMPOSITION.**

The new infrastructure candidate is the **Card Reader Crossing Membrane**: a local doorway through which physical or represented cards can enter an actual interaction surface, be recognized under that surface's own law, participate in an action, and leave an attributable local receipt.

The systems remain orthogonal.

A player may begin in REALITY.2 without knowing postEmahh'n.

```text
REALITY.2
```

# 2. ARITY IS LOCAL

The system is neither globally solo nor globally multiplayer.

Instead, individual nouns, verbs, relations, gates, and appointed events may declare how many distinct participant positions are required for that particular relation to exist.

Candidate notation:

```text
n_min(x)
```

Examples:

```text
COMPOSE
n_min: 1
```

```text
POST
n_min: 1
```

```text
MUTUAL WITNESS
n_min: 2
```

A future BAND relation may require higher arity.

Core non-collapse:

> **PLAYER COUNT != RELATION ARITY.**

A single player can operate the converged grammar.

A single player cannot counterfeit a relation whose constitution actually requires another irreducible participant position.

# 3. THE SOLO GAME IS A FIRST-CLASS FORM

The single-player form is not "multiplayer with imaginary opponents."

Its mechanic ancestors are closer to:

```text
solitaire arrangement
x choose-your-own-adventure consequence
x Tarot-like relational spread / symbolic compression
x Myst / Cyberprophecy / Cicada-style hidden aperture
```

These are design ancestors, not claims of shared creator intent or common ontology.

The important imports are structural.

## 3.1 TABLEAU = CURRENT WORLD

Arrangement itself is state.

```text
same cards
+ different placement
= different current world
```

A card's operative meaning may depend on:

```text
CHARACTER
+ POSITION
+ NEIGHBORS
+ WORLDLINE
+ CURRENT QUESTION
+ ACTIVE DECODER
```

## 3.2 SPREAD = TEMPORARY EXECUTION FRAME

A spread can function as a local decoder.

Examples:

```text
WHAT ARRIVED
WHAT HOLDS
WHAT MAY LEAVE
```

which directly echoes:

```text
RECEIVE
HOLD
POUR
```

Another spread may ask:

```text
SOURCE
CROSSING
DESTINATION
```

The same deck may therefore support multiple lawful readings without silently asserting one universal ontology.

## 3.3 CYOA = CONSEQUENCE, NOT PAGE NUMBER

A choice changes reachable future state.

```text
S_t
 --choice-->
S_(t+1)
```

Narrative emerges from state transition and preserved receipts rather than requiring every story branch to be authored in advance.

## 3.4 APERTURE = NEWLY DISCOVERED AFFORDANCE

An old object may become newly readable under a later decoder.

```text
OLD OBJECT
+ NEW DECODER
-> NEW APERTURE
```

But:

```text
NEW DECODER
!=
RETROACTIVE NEW HISTORY
```

Later understanding may change future use.

It may not rewrite what happened earlier.

The Myst / Cyberprophecy / Cicada-like layer is not primarily a prewritten fictional mystery.

Working law:

> **GRAMMAR STAYS PORTABLE. CAPABILITIES STAY LOCAL.**

# 5. ANYTHING, IF LAWFULLY SUBMITTED

The strong design direction is not to divide cards into intrinsically "safe" and "dangerous" classes.

Instead:

```text
CARD DOES NOT AUTHORIZE THE ACTION.
A LAWFULLY CONSTITUTED SUBMISSION DOES.
```

A submission may contain:

```text
characters
formation / arrangement
active decoder
interaction history
actor context
target surface
requested relation or action
```

The local system asks:

> **DO I RECOGNIZE THIS AS A LAWFUL REQUEST HERE, NOW?**

"Anything" therefore means:

> Any operation the current surface knows how to perform for which the submitted formation satisfies that surface's own recognition, authority, scope, arity, timing, and consequence rules.

Cardboard does not bypass:

```text
operating-system permissions
account credentials
external service authorization
human gates
local policy
capability boundaries
```

Those remain part of the law being checked.

Existing law survives:

> **CAPABILITY != AUTHORITY.**

> **POSSESSION != AUTHORITY.**

# 6. COPYING IS ENCOURAGED

The convergence rejects artificial scarcity as the primary identity mechanism.

Cards may be:

```text
printed
photocopied
redrawn
shared
remixed
given away
reproduced
```

Working law:

> **COPYING IS A FEATURE.**

The system should not depend on enforcing exclusivity it cannot reliably observe.

A copied card remains a valid presentation of a recognizable Character when the local surface recognizes it as such.

Important distinction:

```text
PRINTED SURFACE
!=
INTERACTION HISTORY
```

and:

```text
COPY OF RECEIPT
!=
NEW OCCURRENCE OF RECEIPTED EVENT
```

Copying an image does not cause the historical event represented by an old receipt to happen again.

A copied carrier can begin a new road.

Generated compression:

> **COPYING CREATES A FORK, NOT A COUNTERFEIT.**

# 7. CHARACTER, CLAIMED WORLDLINE, LOCAL ENCOUNTER

The system should avoid pretending a camera can always prove which exact piece of paper has returned.

Preserve three distinct layers:

```text
CHARACTER
!=
CLAIMED WORLDLINE
!=
LOCAL ENCOUNTER
```

## CHARACTER

What the surface recognizes the presented form as.

Example:

```text
LEMON
```

## CLAIMED WORLDLINE

History presented with the carrier.

This may include earlier receipts, lineage references, marks, prior surface interactions, or descendant claims.

The receiving surface may inspect these claims without silently adopting them as its own observations.

## LOCAL ENCOUNTER

What the current surface can witness directly:

> **THIS PRESENTATION CROSSED THIS MEMBRANE NOW.**

This is the hard local receipt.

Even an anonymous hand-drawn card can therefore acquire an attributable local encounter.


```text
receive != accept

arrival != authority

received-from != authorized-by
```

And it inherits DOORWAY-3:

```text

  -> CROSSING MADE PARTICULAR
  -> DESTINATION
```

The membrane is the explicit third position.

It preserves enough structure to distinguish:

```text
what arrived

what the local surface recognized
what was requested
what authority was available
what was refused
what was held
what action occurred
what changed
what receipt was created
```

Working compression:

> **THE CARD READER IS NOT REALLY A READER. IT IS A DOORWAY.**

# 9. EVERY INTERACTION SURFACE IS ITS OWN WORLD

A critical design step is to treat distinct interaction surfaces as distinct witnesses.

Examples may include:

```text
one Static Workbench installation
another person's Workbench installation
Haunted Toaster
Haunted Blender
a Room surface
a physical installation
a future local tool or game surface
```

Even if two surfaces share code or grammar:

```text
SURFACE_A != SURFACE_B
```

Each keeps its own local memory of crossings.

So a card may have:

```text
Surface A:
  8 witnessed encounters

Surface B:
  3 witnessed encounters

Surface C:
  11 witnessed encounters
```

This is not automatically "22 XP."

It is:

> **22 locally witnessed crossings distributed across three distinct worlds.**

The topology may matter more than the count.

# 10. LOCAL RECEIPT LOG

Each interaction surface keeps its own append-oriented receipt log.

Candidate conceptual record:

```text
encounter:
  local_receipt_id
  surface_id
  observed_character
  presented_worldline_claims
  active_decoder
  formation / companions
  requested_action_or_relation
  local_authority_context
  disposition
  resulting_delta
  timestamp
  resulting_receipts
```

This is design material, not a frozen implementation schema.

The important law is:

> **EVERY WORLD KEEPS ITS OWN MEMORY OF WHAT CROSSED ITS OWN DOOR.**

No universal master ledger is required.

One surface may truthfully say:

> I encountered this Character six times.

Another may truthfully say:

> I encountered a presented descendant of this lineage twice.

A third may say:

> This Character participated in three scene generations and one refused crossing.

These are different witnesses.

They need not collapse into one omniscient record.

# 11. LOCAL RECEIPTS DO NOT BECOME GLOBAL TRUTH

A local surface owns its own observation.

It does not automatically own the meaning of the entire lineage.

```text
LOCAL RECEIPT
!=
GLOBAL TRUTH
```

Cross-surface systems may later compare receipts.

They should preserve source attribution.

```text
Surface A says X.
Surface B says Y.
Surface C has no observation.
```

is better than:

```text
THE CARD IS X.
```

unless a higher-order decoder has lawfully constituted that stronger claim.

This preserves the existing project posture:

> **GENERATED != GIVEN.**

> **RECEIPT != TRUTH.**

> **RECEIPT = ATTRIBUTABLE TRACE OF A CROSSING.**

# 14. RECEIVE → HOLD → POUR BECOMES PHYSICAL PLAY

The older three-verb grammar becomes a direct card-crossing mechanic.

## RECEIVE

What actually arrived?

Preserve presented material without silently treating it as true, trusted, canonical, executable, or authorized.

## HOLD

Keep the crossing particular long enough to inspect:

```text
character
claims
source
lineage
local context
authority
companions
decoder
unresolved remainder
```

## POUR

Emit a locally constituted result onward.

The thing poured need not be identical to the thing received.

```text
X_A
  -> receive
  -> hold
  -> local transformation
  -> pour
  -> Y_B
```

The road remains attributable.

# 15. APPOINTED MEETINGS AND THREE CLOCKS

Some relations require multiple participant positions.

Those positions need not always be occupied at the same physical time.

A useful inherited distinction is:

```text
PULSE / NOW
THREAD / MAIL
LINEAGE / HEIR
```

## PULSE / NOW

A relation requiring concurrent presence.

## THREAD / MAIL

A relation that can be constituted asynchronously through addressed crossings.

## LINEAGE / HEIR

A relation whose required participant may not yet exist.

This permits an appointed meeting to remain open until its declared conditions are actually met.

Candidate structure:

```text
MEETING
appointed_at
required_roles
n_min
gate
inputs
witness
result
receipt
```

An appointment does not manufacture the meeting.

It creates an addressable opening.

Working law:

> **THE MEETING HAS A BIRTHDAY WHEN THE REQUIRED RELATION ACTUALLY EXISTS, NOT MERELY WHEN IT WAS PROPOSED.**

# 16. SYSTEM-PRINTED CARDS

The code world may print cards that it currently knows how to recognize.

This does not make those cards artificially scarce or uniquely authentic.

Instead, printing is a way for the system to externalize its currently recognized grammar into portable physical Characters.

```text
CODE WORLD
  -> PRINT
  -> PHYSICAL CHARACTER
  -> PLAY
  -> CROSSING
  -> CODE WORLD'
```

The image may be freely copied.

The useful distinction is:

```text
RECOGNIZABLE CHARACTER SURFACE
!=
ITS FUTURE INTERACTION HISTORY
```

The strongest formulation is:

> **THE SYSTEM PRINTS THE CARDS THAT CAN LAWFULLY SPEAK BACK TO IT.**

Not because the ink contains authority.

Because the local membrane knows how to parse the Character and evaluate the submitted relation under current law.

# 21. NO MASTER LEDGER

A centralized global history is not required for the core architecture.

Default topology:

```text
                CARD
                 |
      -----------+-----------
      |          |          |
      v          v          v
  Surface A   Surface B   Surface C
      |          |          |
  membrane    membrane    membrane
      |          |          |
  ledger A    ledger B    ledger C
       \          |          /
        \---------+---------/
                  |
          optional later
       cross-world decoder
```

Each local ledger can stand as its own witness.

This aligns with the 13th Cup architecture:



