# PROVENANCE-KNOT-001 — THE SCRIPTURE IN YOUR EARS / THREE AUTODISCO CANONS

**Date:** 2026-09-23  
**Posture:** research specimen / CANDIDATE, not a constituted case or source-project canon.  
**Question:** Can one identifiable textual or musical work participate in multiple later encounters and separately constituted editions without any edition retroactively authoring the source event, and without collapsing the histories of publication, arrangement, order, credit, and reception into one lineage?

## Why this specimen

The motivating artist reports that The Static Collective's YouTube catalog and Bandcamp catalog differ in **order, composition, and attribution**, while Auto Disco v20 constitutes a third programming/encounter surface. These are **artist-reported cross-platform differences**, *not yet* independently audited item-level metadata. They are not permission to assume each platform's item with the same title contains identical audio or credits.

This is a concrete laboratory for the broader question, “Why can an old text remain embedded in ongoing reality?” A work may have a traceable origin but multiple later entrances, readers, translators, performers, editors and audiences. A later entrance contributes a **new historical event**, not a rewrite of the original.

**Working compression:** `same source ≠ same textual witness ≠ same editorial edition ≠ same individual encounter`.

### A real delta, rather than “everything is the same”

- **Earlier Isaiah carrier → Luke 4 account:** Luke's version is a selected/composite appropriation. Isaiah 61:2's “day of vengeance” does not appear in Luke 4:19, while language associated with Isaiah 58:6 is present in Luke 4:18. This is a textual selection and reuse, not merely unchanged copy/paste. Interpretive explanations of the selection must be attributed, not adopted as proven authorial motive.
- **Luke's account → translation/paraphrase:** “your ears/hearing” in more literal renderings versus a paraphrastic presentation of immediate fulfillment in TLB is a receiver-facing *wording and emphasis* change, not a change to the alleged first-century event.
- **Text → song construction:** Re-phrasing the “TODAY” utterance into rhythm, stress, and performed music creates a new reception/composition event, retaining an attributable source relation while making new artistic decisions. Even if sung from a verbatim English translation, it would remain a new performance.
- **Song → a particular platform item:** An upload or album placement, when verified, is a new publication/edition event with its own sequence, notes, credits, media hash and audience window. No platform gets to overwrite the authored track history simply by publishing it.

The stronger insight: **editorial order itself is an encounter-forming operation**. If the same song appears after two different predecessors, listeners may have different locally available context even if the song audio bytes are identical. If different masters/credits appear, we must first check whether they are the same recording, an alternate take, a derivative arrangement, or merely title collision.

## Minimal receipt / strict admission gate

Every proposed item comparison should carry:

```text
work_candidate_id                 // hypothesis, never derived solely from matching titles
occurrence_id                     // composition, performance, upload, playlist placement, broadcast, etc.
source_locator                    // exact text verse/edition or platform item ID/URL
source_sha256 / media_sha256      // when actual bytes are lawfully available; otherwise absent
carrier_type                      // manuscript family / printed edition / translation / lyric / audio / video / broadcast
edge_type                         // cites / translates / paraphrases / performs / records / uploads / places / broadcasts / reports / compares
edge_basis                        // witnessed / primary-source metadata / user-reported / inference / unresolved
event_time / observed_at          // distinct; unknown stays unknown
publisher_or_editor               // only when evidenced
composer / writer / performer / generator / uploader / curator / commentator
                                // independent roles; never copied from a platform account name
ordinal_and_container             // album, playlist, program sequence and cut date
receiver_constitution             // edition, audience context, bounded DJ knowledge, if relevant
disposition                       // verified / held / refused
nonclaims                         // what the edge does not establish
```

Identity assertion requires **positive bridge evidence** (provider IDs, authenticated metadata, audio comparison with rights/access, an artist-confirmed master manifest or a documented derivative relationship). Matching title, recurring lyrics, thumbnail, numeral, upload sequence or model's semantic guess can only create a candidate correspondence. Credit attribution never propagates automatically across carriers: e.g., uploader ≠ lyricist ≠ performer ≠ producer ≠ editor.

**First real Auto Disco cross-platform test:** choose one artist-confirmed work candidate, inspect one YouTube item and one Bandcamp item at independently timestamped cuts, and place a third *bounded candidate* programming slot in v20. Compare (a) recorded order, (b) audio/master or composition identity, (c) credit role statements, and (d) each surface's encounter context. If no matching item can be verified, retain three separate nodes and mark the bridge `HELD`. Do not invent a shared work ID or claim v20 played it.

## Hostile controls

1. **Same title, different track:** two recordings called “TODAY” cannot be co-identified from title alone.
2. **Same audio, different sequence:** media identity can survive while album/playlist/broadcast context and editorial chronology differ.
3. **Same audio, changed credit:** preserve conflicting platform claims and distinct role/time sources; do not select a winner or infer a transfer of authorship.
4. **A fresh listener hears a repeat:** a v20 first-listen DJ cannot claim station-level historical knowledge without explicit permission; the station may still store a cross-catalog history.
5. **New reception doesn't rewrite ancient source:** SC-LYRIC can genuinely change the history of *the passage's reception* without establishing Luke's historical date, Jesus' original speech language, or the first-century audience's response.
6. **Coincidental common language:** lyrical resemblance to Scripture without documented exposure is marked as resemblance, not descended-from.
7. **Different theological / editorial senses of canon:** sharing a word doesn't merge their authority or membership criteria.
8. **Edition versus publication:** reordered packaging may be an editorial edition; a changed audio master needs new media identity even if the work family is retained.

## What a successful specimen would actually establish

A typed graph showing one documented ancient textual reuse (Isaiah ↔ Luke), one *conversation-witnessed* modern artistic reception, and three held publication/broadcast candidates. It would demonstrate a **method for retaining multiple local histories**, not prove a continuous, exhaustively reconstructed causal chain from first-century event to 2026 song. The project must not treat this thread as a newly landed full case merely because it has a filename.
