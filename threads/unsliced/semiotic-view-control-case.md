## 1. Peirce control — meaning as relation, not payload

### Working lead

Peircean semiotics models signification through a triadic relation involving a sign, an object, and an interpretant rather than treating meaning as a fixed substance stored inside the visible mark.

That rhymes with the current relational-coordinate hypothesis:

```text
SIGIL / COORDINATE Σ
        ↓ resolve
       OBJECT O
        ↓ typed lens L
   PROJECTION P_L(O)
```

The potentially useful continuity is narrow:

> meaning may be generated through a constrained relation among sign, object, and interpretation rather than residing entirely inside the mark.

### Required restraint

This must **not** become:

```text
Σ + arbitrary observer
→ arbitrary meaning
```

The stronger candidate is:

```text
Σ + attributable interpretive relation
→ constrained projection
```

Peirce is useful here only if the object/sign relation constrains interpretation enough to supply a real anti-arbitrariness pressure test.

### Research still needed

- Pin primary and high-quality secondary Peirce sources for sign / object / interpretant.
- Determine where the analogy breaks: an interpretant is not obviously identical to a versioned software decoder or explicit typed lens.
- Ask whether Peirce contributes any falsifier that Free Graph #2 does not already contain.

## 2. Database view control — one object, several purpose-shaped projections

### Working lead

Database view theory provides a practical analogue in which one underlying database can support several application-specific views.

Conceptually:

```text
underlying object / database O
        ├── P_math(O)
        ├── P_lineage(O)
        └── P_topology(O)
```

The useful pressure is not merely "many views." It is the **view-update problem**.

A read projection can hide information. Therefore an edited view does not generally determine one unique underlying source mutation.

```text
source
  ↓ project
view
```

is not automatically invertible as:

```text
changed view
  ↓ ???
unique changed source
```

### Candidate Collective boundary

This externally pressures an invariant already present in the sigil work:

```text
projection != consequence
```

A lawful projection of an object does not by itself authorize mutation of that object.

### Research still needed

- Pin the classical database-view / view-update sources referenced by the originating research pass.
- Separate what is specific to relational databases from what actually transfers to typed eCODE projection.
- Identify a counterexample where two distinct underlying objects yield the same visible projection.

## 3. Bidirectional-lens control — GET is not PUT

### Working lead

Bidirectional transformation research makes the asymmetry more explicit by separating a forward projection from the governed operation that propagates a changed view back toward a richer source.

The useful compression is:

```text
GET / PROJECT
O → P_L(O)
```

versus:

```text
PUT / CONSTITUTE
(P_L(O)', O, local policy)
→ O'
```

If the view discarded information, a reverse update may need both the modified view and additional source context. The reverse operation therefore cannot be inferred merely from the existence of the readable projection.

### Candidate Collective boundary

```text
legibility
    !=
mutation capability
    !=
mutation authority
    !=
constituted consequence
```

A future eCODE implementation may eventually have a lawful write-back path, but that path would require its own local gate, authority model, causal accounting, and lineage.

### Research still needed

- Pin the foundational bidirectional-lens paper(s) and the relational-lens follow-on work.
- Test whether lens laws such as round-tripping are useful analogues or misleading imports.
- Keep software "lens" terminology distinct from the broader Collective use of `lens` unless executable pressure proves they should converge.

## 4. Why this matters to Relational Coordinate

The current sigil hypothesis is stronger if it survives controls from fields that independently discovered similar separations:

```text
stable coordinate Σ
      ↓
resolves attributable object O
      ↓
versioned typed lens L
      ↓
projection P_L(O)
```

The proposed external-control contribution is:

1. **Peirce:** interpretation is relational and constrained, not merely intrinsic to the mark.
2. **Database views:** one source may lawfully expose several partial views.
3. **View-update theory:** a visible view may omit facts needed to reconstruct the source.
4. **Bidirectional lenses:** projecting and propagating changes are distinct operations with different information requirements.

None of those, separately or together, proves the Static Collective architecture.

They are useful only if they sharpen falsifiable boundaries already under pressure.

## 5. Standing anti-collapse boundaries

Preserve all of these while this remains unsliced:

```text
interpretation != evidence
lawfully decoded != factually true
projection != complete object
projection != authority
projection != consequence
readability != write capability
write capability != local authorization
external analogy != ancestry
structural convergence != proof
```

## 6. Candidate specimen pressure

Do **not** create a new schema for this control packet.

The cheapest executable use remains Free Graph issue #2.

A useful fixture would preserve:

- one stable coordinate;
- several explicitly typed/versioned lenses;
- at least two projections that differ under lens change;
- at least one pair of visually equivalent projections with different ancestry;
- fixed identity, ancestry, authority, access, and export posture where the test says they must remain invariant;
- an attempted projection edit that cannot silently mutate the underlying object.

The last item is the only genuinely new pressure suggested by this external-control packet:

> **Can the system make a projection editable or transformable without smuggling a view update into source constitution?**

That should remain a question until an owner-local specimen exists.
